Lesson 10 · 打通与落地

打通语义层与业务系统

让本体真正落到关系库 + 领域模型(DDD)之上,给业务带来可见收益

上一课讲怎么带团队。这一课讲技术怎么打通:让本体(语义层)真正坐在你的关系库和领域模型之上,而不是停留在 PPT 或代码注释里。而且——这不是空想,行业有成熟的标准和产品在做。

01一个心智模型:四层各司其职

别把本体当成"另一个数据库"。把它想成一层"语义视图",叠在你的系统之上:

图 1 · 关系库仍是权威记录;本体作为上面的"语义层";AI 从语义层取数。三层不是替代,是叠加。

层负责世界
记录层(关系库 + DDD 聚合)权威数据、事务、业务行为闭世界
语义层(本体 / 知识图谱)共享语义、校验、推理开放世界
AI 层(大语言模型)从语义层取事实来回答/报告—

02打通关系库 ↔ 本体:W3C 标准

把数据库"翻译"成本体,有官方标准:

方式怎么做适何时
Direct Mapping自动:表→类、行→个体(用主键做标识符)、列→属性先快速得到"有 RDF 视图"
R2RML(关系库到 RDF 的映射语言)你写映射:把列/查询视图对齐到既定本体术语要对齐行业本体(如 SCOR)
# 一个 R2RML 片段:把 product 表映射到本体类 :ProductMapping rr:logicalTable [ rr:tableName "product" ] ; rr:subjectMap [ rr:template "http://ex.org/product/{product_id}" ; rr:class :Product ] ; rr:predicateObjectMap [ rr:predicate :hasLeadTime ; rr:objectMap [ rr:column "lead_time_days" ] ] .

读作:每行 product → 一个 :Product 个体(用 product_id 做标识符),它的 lead_time_days 列映射成本体属性 :hasLeadTime。这就是"把数据库对准本体"。

03虚拟 还是 物化?

本体语义层要"活在"哪?两条路:

方案怎么做优点代价
虚拟(推荐)用本体数据访问(OBDA),如 Ontop:把关系库当虚拟知识图谱,SPARQL 自动转成 SQL数据不搬家、永不过时、零冗余性能取决于改写质量
物化ETL 把三元组拷进图库遍历/多跳/AI 检索快冗余、需同步、新鲜度打折
选型一句话:要"实时、不搬家"→ 虚拟(Ontop);要"图遍历/检索性能"→ 物化。多数场景可先虚拟,必要时局部物化。

04和领域模型(DDD)打通:共享词 + 语义契约

本体和 DDD 不是二选一——它们是同一领域不同层的两张视图。打通的法子是共享词汇 + 语义契约:

  • 本体定义跨上下文都要对齐的共享概念(Product、Forecast、Capacity……)。
  • 各 DDD 有界上下文里的 *ubiquitous language* 与本体术语保持一致(而非各叫各的)。
  • 本体是"契约层";DDD 聚合仍在代码里管行为、事务。
一句话

本体让不同上下文说同一种话,DDD 让每个上下文把话说对、把事办对。两者是互补,不是竞争。

收益具体表现

06一个最小落地,走一遍

拿一张真实链路:product / order 表 → 本体 → 回答"这个 SKU 为什么排不下来?"

  1. 映射:用 R2RML 把表映射到本体(Product、Order、hasLeadTime、requiresProduct)。
  2. 虚拟化:Ontop 让语义层"坐在"关系库上,SPARQL 即查即得(SQL 改写)。
  3. 查询 + 推理:沿本体多跳(:order-1042 :requiresProduct ?sku、:sku-447 :isProducedOn :line-7、:line-7 :hasCapacity ?cap),推理器补全。
  4. AI 回答:大语言模型基于这些结构化事实给出"受产能/提前期限制"的有据结论。
  5. 校验:用公理检查答案与注入事实无矛盾。

你能拿到的"可见收益":一个以前靠"看文本瞎猜"的 AI 问答,变成了"基于确定事实推算"——准确率、一致性、可审计性都肉眼可见提升。

07行业实践(有据可查)

  • W3C:R2RML 与 Direct Mapping —— 关系库↔RDF 的官方标准。
  • Ontop(OBDA):开源,把关系库当虚拟知识图谱,SPARQL→SQL。
  • Microsoft Fabric IQ(本体):业界产品——定义实体类型/属性/关系,绑定真实数据,暴露给分析、AI 代理、应用。
  • Gartner / Forrester:语义层/知识图谱正成为企业 AI 的核心上下文基础设施;语义方法驱动 GenAI 价值。
  • 供应链:SCORVoc,对齐行业标准。
